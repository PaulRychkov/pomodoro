# Pomodoro — помидор-таймер экосистемы

Настольное приложение под Windows 10/11 (Wails v2): единый Go-процесс с UI на React, embedded REST/MCP API и публикацией событий в Kafka. Главный источник фактов работы для бота-мотиватора: «помидоры идут — работа идёт».

## Возможности

- Стейт-машина таймера: `idle → focus → short_break / long_break`. Структура дня берётся из плана: блок кончается длинным перерывом или границей периода, `day_blocks` в настройках лишь задаёт ритм длинных перерывов (после каждых `day_blocks[0]` помидоров внутри периода). В `idle` таймер показывает длительность следующей сессии по плану (`state.next_planned_seconds`), а не дефолт из настроек, под ним — «по плану в HH:MM»; перерыв после помидора — перерыв его слота; «помидор X из Y (блок N)» и `day_total`/`day_blocks` в `state` считаются по блокам плана.
- Пауза/резюм с накоплением `paused_total_seconds` (по модели данных v1.0).
- Досрочное завершение с частичным зачётом: кнопка «Завершить» (и такая же в оверлее) заканчивает фокус сейчас и засчитывает долю помидора по фактическому фокусу без пауз, округлённую до ближайшей из 0, ¼, ⅓, ½, ⅔, ¾, 1. Пока идёт фокус, под кнопками видно, сколько засчитается прямо сейчас. Доля хранится в `sessions.credit_twelfths` (в двенадцатых: 0, 3, 4, 6, 8, 9, 12 — без погрешностей), точное время фокуса — в `sessions.focus_seconds`. Доля 0 записывается как брошенный помидор и слот не сдвигает, но время всё равно сохраняется. «Стоп» — бросить без зачёта. В задачи (`POST /occurrences/{id}/progress`) уходят фактические минуты фокуса, а не плановые минуты слота; запись идёт только после фокуса, а не после перерыва. В списке помидоров дня у каждого — точное время и доля, в итоге дня — сумма засчитанного.
- Автостарт перерыва после фокуса и фокуса после перерыва (настраивается).
- «Висящие» сессии (сон/крэш) при следующем запуске закрываются как `interrupted`.
- Привязка «что делал»: текстовая метка ИЛИ задача из внешнего источника (REST tasks, URL настраивается); ретро-привязка завершённых сессий за день.
- План помидоров дня привязан ко времени суток. Активный день (`day_start_minutes` / `day_end_minutes`, по умолчанию 06:00–20:00) режется на периоды: свободное время между событиями и «окна» — задачи с фиксированным временем и помидорами (например, «Работа» 10:00–19:00). События без помидоров (`requires_pomodoro=false`: обед, зал, дорога) вырезаются из дня, всё за границами активного дня игнорируется. У каждого слота есть плановое время старта, слот не пересекает границу своего периода и конец дня. Число помидоров в дне определяет вместимость дня, а не сумма `day_blocks`. Гибкие задачи (`effort_minutes`, помидор ≈ длительность фокуса) получают оставшиеся слоты по трудозатратам и весу приоритета; не влезшее уходит в секцию «Не влезли в день» в конце плана, без времени. Каждый слот редактируется вручную (задача/метка + индивидуальные длительности фокуса/перерыва, `-1` — вернуть значение плана), правки переживают пересборку; «Фокус» берёт задачу из первого невыполненного слота.
- Доля окна: `window_share_percent` (по умолчанию 67) от всех помидоров окна за день, включая сделанные (округление до ближайшего), достаётся задаче окна; остальные — другим задачам, равномерно по окну (при доле от 50% два «чужих» помидора подряд не идут). 100% — в окне только его задача, 0% — время окна полностью свободно для других задач. Помидоры задачи окна из своего окна не уходят; вхождение задачи-окна не закрывается автоматически до конца окна.
- Подгон длин под периоды: каждый период заполняется ровно (`FitPeriod`) — фокус ужимается не ниже 2/3 настроенного, перерывы никогда не короче настроенных, длинный перерыв ставится после каждого блока из `day_blocks[0]` помидоров внутри периода. Если следующий период начинается вплотную, в конце текущего резервируется короткий перерыв, чтобы следующий начался вовремя. Пример (день 06:00–20:00, фокус 25 / перерывы 5 и 15, сборы 6:40–7:00, зал 7:00–7:40, дорога 7:40–8:00, «Работа» 10:00–19:00, обед 14:00–15:00): 24 помидора — 6:00–6:40 два по 17 минут (чистого фокуса больше, чем у одного на 25), 8:00–10:00 четыре, в каждой половине работы по восемь (16 в окне: 11 «Работе», 5 другим, равномерно), 19:00–20:00 два по 25. Ручная правка слота и пресет на день перекрывают автоматические длительности.
- Пересчёт от факта: прогнозный старт слота — максимум из цепочки от текущего момента (идущий помидор, ожидающий перерыв, пауза) и его планового времени. Пришёл раньше — больше отдыха, опоздал — съедается период. Сделанные слоты показывают реальный старт, идущий держит свой. Если несделанный слот уже не помещается в свой период, план пересобирается от текущего момента (сделанные и идущий заморожены): текущий период укладывается заново (помидоры короче или меньше), рабочие окна остаются на своих временах, доля окна считается от всего окна. Расчёт полностью арифметический.
- Автостарт перерыва по умолчанию выключен: план опирается на реальные моменты старта, поэтому перерыв начинается тогда, когда его начали.
- Интерфейс плана: слоты сгруппированы по периодам с заголовками вида «10:00–14:00 · Работа» и счётчиком «Работа 5 из 8 · другие 3», в конце — «Не влезли в день · N». План перечитывается раз в минуту и при смене состояния. В браузерном/Android-режиме (опрос состояния) причины обновления (`started`, `completed`, `stopped`, `paused`, `resumed`, `settings`, `day_rolled`) выводятся из разницы снимков состояния, поэтому план, список сессий и сигнал окончания обновляются так же, как на десктопе.
- Пресеты помидорного дня: текущий план (число слотов + длительности) сохраняется под именем и назначается на дни недели; в день с пресетом помидоры раскладываются из него по порядку (не влезающий в период переносится в следующий, не влезающие в день отбрасываются), без пресета — подгоном под периоды дня.
- Прогресс дня: горизонтальные точки по блокам, длинные перерывы визуально отделены увеличенным расстоянием.
- Оверлей: маленькое frameless always-on-top полупрозрачное окно поверх всех приложений с убывающим круговым таймером; перетаскивание мышью, размер/прозрачность/цифры настраиваются на лету; двойной клик по кругу (или Esc) — вернуть главное окно; при остановке таймера оверлей сам возвращается в главное окно.
- Звук окончания: встроенный сигнал (go:embed) или свой файл (wav/mp3/ogg), воспроизведение на фронте через HTML Audio.
- Персистентность: PostgreSQL 16 (GORM + golang-migrate), outbox → Kafka `pomodoro.events` (CloudEvents 1.0, только focus-события). Недоступность Kafka работе не мешает — события копятся в outbox.

## Запуск

1. PostgreSQL — в каталоге проекта (Docker в WSL):

```powershell
wsl -d Ubuntu-22.04 -- docker compose up -d
```

2. Kafka (опционально) — в каталоге `infra/` экосистемы:

```powershell
wsl -d Ubuntu-22.04 -- docker compose up -d
```

3. Сборка и запуск:

```powershell
wails build
.\build\bin\pomodoro.exe
```

Фронт собирается автоматически (`-s` — пропустить пересборку фронта). Режим разработки: `wails dev`.

## Конфигурация

`.env` в каталоге проекта или рядом с исполняемым файлом (образец — `.env.example`), переменные окружения с префиксом `POMO_` имеют приоритет.

| Переменная | По умолчанию | Смысл |
|---|---|---|
| POMO_HTTP_PORT | 8082 | порт embedded API+MCP |
| POMO_DB_HOST / POMO_DB_PORT | localhost / 5434 | PostgreSQL |
| POMO_DB_USER / POMO_DB_PASSWORD / POMO_DB_NAME | pomodoro | доступ к БД |
| POMO_DB_SSLMODE | disable | sslmode |
| POMO_KAFKA_BROKERS | localhost:9094 | брокеры через запятую |
| POMO_KAFKA_TOPIC | pomodoro.events | топик событий |
| POMO_TASKS_URL | http://localhost:8081 | внешний источник задач |
| POMO_TASKS_SOURCE | tasks | значение `source` в привязке |
| POMO_LOG_LEVEL | info | debug/info/warn/error |

Пользовательские настройки таймера (длительности, блоки дня, автостарты, звук, оверлей, раскладка плана дня) живут в таблице `settings` и редактируются в UI и через MCP. Раскладка плана: `day_start_minutes` / `day_end_minutes` (активный день в минутах от полуночи, по умолчанию 360 / 1200 = 06:00–20:00; в UI — «Настройки → План дня», поля «Начало дня» и «Конец дня»), `window_share_percent` (по умолчанию 67) и `day_blocks` (ритм длинных перерывов). Настройки `plan_before_window_minutes` / `plan_after_window_minutes` убраны: колонки в БД остались, но не используются. Миграции: PostgreSQL `0009_day_bounds`, SQLite `0004_day_bounds` (границы дня в `settings`, плановое время/период/окно/«не влезло»/ручные длительности в `plan_slots`).

Дополнительно (мобильное и синхронизация): `POMO_DB_DRIVER` (`postgres`/`sqlite`), `POMO_DB_PATH` (файл SQLite), `POMO_SYNC_URL` / `POMO_SYNC_TOKEN` / `POMO_SYNC_INTERVAL_SECONDS` — двусторонняя синхронизация сессий, настроек, пресетов и расписания с ПК.

## Мобильное приложение (Android)

Тот же движок помидора, тот же план и тот же фронтенд (`frontend/`) под телефон, без дублирования.

- `mobile/` — gomobile-пакет: движок + план + REST/RPC на **SQLite** (`ncruces/go-sqlite3`, без сисколлов — иначе seccomp Android убивает процесс) на `127.0.0.1:18082`, раздаёт собранный `frontend` как статику.
- `android/` — Kotlin-обёртка (WebView + настройки: URL tasks, URL/токен синхронизации).
- `frontend/src/api.ts` получил REST-адаптер: в Wails — через биндинги и события; в мобильном/браузере — через `/api/v1/rpc` и опрос состояния. Один и тот же React-код работает и на десктопе, и на телефоне.

Сборка: `deploy\build-android.ps1` (фронт → `mobile/webdist` → `gomobile bind` → gradle APK).

## API (localhost:8082, префикс /api/v1)

- `GET /healthz` — статус.
- `GET /api/v1/state` — снапшот стейт-машины (фаза, остаток, блоки дня).
- `GET /api/v1/sessions?from&to` — сессии за период (RFC3339 или YYYY-MM-DD, по умолчанию сегодня).
- `GET /api/v1/sessions/active` — активная сессия (`session: null`, если нет).
- `POST /api/v1/sessions` — старт: `{kind: focus|break|next, label?, task?{source, external_id, title_snapshot}}`.
- `POST /api/v1/sessions/{id}/stop` — `{outcome: completed|abandoned}` (по умолчанию abandoned). `completed` до конца таймера — досрочное завершение с частичным зачётом; в `state` появляется `credit_today` — сумма засчитанных долей за день.
- `POST /api/v1/sessions/{id}/pause` / `POST /api/v1/sessions/{id}/resume` — пауза/резюм.
- `PATCH /api/v1/sessions/{id}` — ретро-привязка `{label}` или `{task}`.
- `GET /api/v1/settings` / `PUT /api/v1/settings` — настройки.

Ошибки: `{"error":{"code":"...","message":"..."}}` (`session_active`, `no_active_session`, `already_paused`, `not_paused`, `not_active`, `not_found`, `invalid_input`, `not_focus`).

API рассчитано на локальное использование одним пользователем: аутентификации нет, CORS открыт (`*`), чтобы MCP-клиенты и локальные инструменты работали без настройки. Осознанный компромисс: любой сайт в браузере может дёргать `localhost:8082`; не выставляйте порт наружу.

## MCP (localhost:8082/mcp, streamable HTTP)

Тулы: `get_active_session`, `start_focus`, `stop_session`, `get_today_stats`, `get_day_plan`, `set_plan_slot` (задача/метка слота + индивидуальные `focus_minutes`/`break_minutes`, -1 — вернуть значение плана), `refresh_day_plan`, `update_plan_settings` (`day_start_minutes`, `day_end_minutes`, `window_share_percent`, `day_blocks`; пустой вызов возвращает текущие значения; после изменения план пересобирается сам).

## События (Kafka `pomodoro.events`, CloudEvents 1.0)

Только для focus-сессий: `pomodoro.started`, `pomodoro.completed`, `pomodoro.abandoned`, `pomodoro.interrupted`, `pomodoro.relabeled`. `subject` = session_id, payload несёт `task {source, external_id, title_snapshot} | null`, `label`, длительности. Завершающие события дополнительно несут `focus_seconds` (точный фокус без пауз), `credit` («3/4») и `credit_value` (0.75). Ключ партиции — aggregate_id.

## Тесты

```powershell
go test ./...
```

- `internal/engine` — стейт-машина: пауза/резюм с накоплением, блоки дня (в том числе из плана) и длинные перерывы, автостарты, interrupted при запуске, ролловер дня, ретро-привязка, валидация настроек, day_blocks и границ дня, `next_planned_seconds` в `idle` и после фокуса/перерыва.
- `internal/plan` — периоды дня (вырезание событий, окна, границы дня), подгон длин помидоров под периоды (`FitPeriod`), инварианты на матрице «настройки × моменты пересборки» (слот не выходит за свой период и день), доля окна и равномерная раскладка, пересчёт от факта (раньше/позже плана, пауза, ожидающий перерыв), ручные правки слотов (закрепление переживает пересборку), «не влезли в день», пресеты, будний день пользователя (`TestPavelsWeekdayPlan`).
- `internal/handler` — httptest: полный REST-контракт, коды ошибок.
- `internal/relay` — конверт CloudEvents, порядок публикации, поведение при недоступной Kafka.
- `internal/tasksclient` — поиск/фильтрация задач, обработка ошибок источника.

### UI-тесты

Playwright-набор в `uitest/` прогоняет все функции таймера в настоящем браузере при ширине десктопа (1280) и телефона (390) против тестового сервера `cmd/uitest-server` (управляемые часы, фейковый tasks API). Запуск: собрать фронтенд (`cd frontend && npm ci && npm run build`), затем `cd uitest && npm ci && npx playwright test`. Подробности (управляющее API стенда, фикстуры, селекторы) — в [uitest/README.md](uitest/README.md).
