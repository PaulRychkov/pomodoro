# UI e2e-тесты (Playwright)

Браузерные тесты таймера и плана дня. Против настоящего бэкенда: SQLite, engine, plan, handler и собранный
фронтенд поднимает тестовый сервер `cmd/uitest-server` — он повторяет проводку `mobile.Start`, но с
управляемыми часами и фейковым task-planner на том же порту.

## Запуск

```bash
# 1. собрать фронтенд (нужен один раз и после каждой правки frontend/src)
npm --prefix frontend ci
npm --prefix frontend run build

# 2. поставить Playwright (браузер не скачивается: используется Chromium из PLAYWRIGHT_BROWSERS_PATH)
cd uitest
npm ci

# 3. прогнать
npx playwright test                      # оба проекта: desktop 1280x900 и mobile 390x844
npx playwright test --project=desktop
npx playwright test tests/timer.spec.ts -g "пауза"
npx playwright test --ui                 # интерактивный режим
```

Playwright сам запускает `go run ../cmd/uitest-server -web ../frontend/dist` и ждёт `/__test/clock`
(первая компиляция Go занимает до пары минут). Уже запущенный сервер переиспользуется (вне CI).

Переменные окружения:

| Переменная        | Назначение                                                              |
|-------------------|-------------------------------------------------------------------------|
| `UITEST_PORT`     | порт сервера (по умолчанию 18090) — чтобы два прогона не делили стенд   |
| `UITEST_WEB`      | каталог собранного фронтенда (по умолчанию `../frontend/dist`)          |
| `UITEST_CHROMIUM` | путь к бинарнику Chromium, если нужен конкретный                        |

Версия `@playwright/test` закреплена на 1.56.1: ей соответствует Chromium revision 1194 из `/opt/pw-browsers`.
При смене версии проверьте `node_modules/playwright-core/browsers.json` — ревизия должна совпасть
с установленной (`ls /opt/pw-browsers`), иначе задайте `UITEST_CHROMIUM`. `playwright install` не нужен.

Тесты идут в одном воркере: у сервера одно общее состояние. Каждый тест начинает с `reset()`.

## Тестовый сервер

`go run ./cmd/uitest-server [-addr 127.0.0.1:18090] [-web frontend/dist] [-tz Asia/Qyzylorda] [-data DIR]`

SQLite-файлы лежат в `$TMPDIR/uitest-server-<порт>` (по умолчанию; каталог чистится при старте, а при
штатной остановке удаляется).

`-tz` выставляет `time.Local`, поэтому план дня не зависит от часового пояса машины (браузер в
`playwright.config.ts` тоже работает в `Asia/Qyzylorda`).

### Часы

Фейковые часы — реальное время плюс сдвиг: таймеры тикают сами, а тест может перепрыгнуть вперёд.
Одни и те же часы у движка и у `plan.Service.Now`. Браузер живёт по настоящему времени: циферблат
отсчитывает вниз локально и подхватывает сдвиг сервера при следующем опросе состояния (раз в секунду).

Ограничение: `rpc/sessions-today` и `GET /sessions` берут границы дня из `time.Now()`, а не из часов
движка. Поэтому дата фейковых часов должна совпадать с реальной датой: `now: "05:50"` (только время)
всегда означает «сегодня» и безопасно. Прыжок через полночь список «Помидоры сегодня» не переживёт.

### Управляющее API (`/__test/*`)

| Запрос                              | Тело / ответ                                                                                                 |
|-------------------------------------|--------------------------------------------------------------------------------------------------------------|
| `POST /__test/reset`                | `{"now", "tasks", "settings"}`, все поля необязательные; ответ `{now, offset_ms, state}`                      |
| `POST /__test/clock`                | `{"now": "..."}` или `{"advance_seconds": N}`; после сдвига сразу `engine.Tick`; ответ как у reset            |
| `GET /__test/clock`                 | `{now, offset_ms}`                                                                                           |
| `GET /__test/tasks-log`             | вызовы planner: `[{at, kind: progress\|complete, occurrence_id, task_id, date, minutes}]`                    |
| `DELETE /__test/tasks-log`          | очистить журнал                                                                                              |
| `GET` / `PUT /__test/tasks`         | прочитать / заменить фикстуру (журнал и выполненные вхождения сохраняются)                                   |

`reset` пересоздаёт всё: новая временная БД (те же миграции, что в `mobile.go`), новые engine, plan и handler;
активный handler подменяется атомарно, старый стек гасится. Без `tasks` фикстура — будний день пользователя.

* `now` — RFC3339, `2026-10-05T05:50:00` (в tz сервера) или `05:50` (это время сегодняшнего дня).
  По умолчанию в `helpers.reset` — `05:50`.
* `tasks` — `{"tasks": [...], "topics": [...]}` или просто массив задач; пропущенная часть остаётся
  по умолчанию, `{"tasks": []}` — день без задач (удобно для чисто таймерных тестов, `NO_TASKS`).
* `settings` — частичный JSON поверх `models.DefaultSettings()` (`overlay` мёржится по полям):
  `{"focus_duration_seconds": 600, "auto_start_break": true, "day_blocks": [1, 2]}`.

Фикстура по умолчанию: события без помидоров (`requires_pomodoro=false`) «Сборы в зал» 400 мин/20,
«Зал» 420/40, «Дорога из зала» 460/20, «Обед» 840/60; окно «Работа» 600/540 (`requires_pomodoro=true`,
приоритет 3); гибкие задачи «Поиск работы» 120 (p3), «Работа с ИИ и другое» 75 (p2), «Английский» 60 (p2),
«Слепая печать» 40 (p2); темы «Карьера», «Развитие», «ИИ».

### Фейковый task-planner (`/__tasks/api/v1/...`)

Тот, что читает `tasksclient`: `GET /topics`, `GET /tasks`, `GET /occurrences?from&to&status` (у каждой
задачи одно вхождение на каждый день диапазона, с вложенным `task`), `POST /occurrences/{id}/progress`
(`{"minutes": N}`) и `POST /occurrences/{id}/complete`. Идентификатор вхождения — `occ_<yyyy-mm-dd>_<task id>`.
Выполненное вхождение исчезает из `status=pending`.

Каждый стек получает свой URL `http://<addr>/__tasks/g<N>` (N растёт с каждым `reset`): запоздавший вызов
из горутины прошлого теста получает 410 и не попадает в журнал следующего. Путь без `g<N>`
(`/__tasks/api/v1/...`) всегда обслуживает текущее состояние — им пользуются тесты и `curl`.

## Селекторы

Основной способ — `data-testid` (см. `PomodoroPage` в `tests/helpers.ts`). Запасные селекторы по роли и
русскому тексту кнопок («Фокус», «Перерыв», «Пауза», «Продолжить», «Завершить», «Стоп») подхватываются
через `locator.or(...)`, так что страница-объект работает и на сборке без части testid.

UI узнаёт об изменениях состояния опросом `/api/v1/rpc/state` раз в секунду (в браузерном режиме
нет push-событий), поэтому после действия ждите ожиданиями `expect(...)`, а не мгновенным чтением.
